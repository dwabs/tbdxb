# Data model

Reference for the Supabase schema as of migration `0028`. Generated by
reading `supabase/migrations/`; if this disagrees with the migrations, the
migrations win — fix this file.

**Read this before writing a migration.** Several problems here have already
been solved in non-obvious ways.

## Enums

| Type | Values |
| --- | --- |
| `booking_status` | `confirmed`, `cancelled`, `completed` |
| `vendor_status` | `pending`, `approved`, `suspended` |
| `vendor_role` | `owner`, `staff` |
| `event_status` | `draft`, `submitted`, `approved`, `published`, `rejected`, `archived` |

`completed` is a real `booking_status` value but nothing in the app ever sets
it. Aggregates therefore filter `status <> 'cancelled'` rather than
`= 'confirmed'`, so the two are equivalent today and stay correct if
`completed` is ever used.

### `booking`

### `event_image`, `event_translation`, `event_view_log`

- **`event_image`** — `event_id`, `url`, `alt`, `width`, `height`,
  `position`. URL may be absolute (vendor upload) or app-relative (seed data).
- **`event_translation`** — PK `(event_id, locale)`, plus `title`,
  `short_title`, `summary`, `body`, `venue`, `area`. Only the public site
  reads it. **The dashboards are English-only and do not write translations.**
- **`event_view_log`** — `event_id`, `viewed_at`. Added `0025` to give views
  a timestamped history for trend charts, since `event.view_count` is a bare
  counter. Only counts from its own deploy date onward — dashboards carry a
  caveat line saying so.

## Views

Both are `security_invoker = on`, which is **load-bearing**: a view defaults
to running as its owner, which would hand every vendor's revenue to any
caller. Because they run as the caller, an unfiltered select returns one row
per vendor the caller can read — always filter by `vendor_id`.

| View | Grain | Columns |
| --- | --- | --- |
| `vendor_event_stats` | per event | `event_id`, `vendor_id`, `title`, `view_count`, `tickets_sold`, `gross_aed`, `net_aed` |
| `vendor_summary_stats` | per vendor | `vendor_id`, `tickets_sold`, `net_aed`, `upcoming_events` |

`net_aed` is the **vendor's** share (`gross × (1 − commission_rate)`). The
platform's cut is `gross × commission_rate` — a different number, computed in
`admin_platform_stats`. Do not mix them up.

## RLS policies

Every table has RLS enabled. Policies are **additive** — a row is visible if
*any* policy allows it.

| Table | Policy | Effect |
| --- | --- | --- |
| `profile` | users read/update own | `auth.uid() = id` |
| `booking` | users read own | `auth.uid() = user_id` |
| | vendors read for own events | events belonging to `my_vendor_ids()` |
| | admins read all | `is_admin()` |
| `vendor` | vendors read own row | via `my_vendor_ids()` |
| | admins read all / manage | `is_admin()` |
| | vendors update own row | self-service, minus revoked columns |
| `vendor_member` | members read own | `user_id = auth.uid()` |
| | admins read all | `is_admin()` |
| `event` | published events are public | `status = 'published'`, anonymous |
| | vendors read/insert/update own | `my_vendor_ids()`; insert forced to `draft` |
| | vendors delete own draft or rejected | |
| | admins read all | `is_admin()` |
| `ticket_type` | follow their event | published, or vendor-owned |
| | vendors manage own | ALL |
| | admins read all | `is_admin()` (`0028`) |
| `event_image` / `event_translation` | follow their event | + vendors manage own (ALL) |
| `event_view_log` | admins read all | inserts happen inside `increment_event_view` |

**There is no customer INSERT policy on `booking`.** It was dropped in `0026`
— all writes go through `create_booking`.

Storage: `avatars`, `event-images`, `vendor-logos` are publicly readable;
writes scoped to the owning user or vendor.

## Functions (RPCs)

All are `security definer` with `set search_path = public`. **Every one that
mutates or exposes data checks authorization in its own body** — RLS does not
apply inside a security-definer function.

### Helpers

| Function | Returns | Notes |
| --- | --- | --- |
| `is_admin()` | bool | `profile.is_admin` for `auth.uid()` |
| `my_vendor_ids()` | setof uuid | Vendors the caller belongs to. The scoping primitive used everywhere |
| `handle_new_user()` | trigger | Creates `profile` on signup |
| `set_updated_at()` | trigger | |

### Customer-facing

| Function | Notes |
| --- | --- |
| `create_booking(event_id, ticket_type_id, quantity, attendee_name, attendee_phone)` | **The only way a booking is created.** Validates auth, quantity 1–16, non-empty name, event published; atomically reserves capacity and returns the reference. Price computed server-side |
| `cancel_booking(booking_id)` | Allowed for the booking's owner, the event's vendor, or an admin. Decrements `quantity_sold` |
| `increment_event_view(event_id)` | Bumps `view_count`, appends to `event_view_log`. Unauthenticated and unthrottled — a known, accepted limitation |

### Vendor-facing

| Function | Notes |
| --- | --- |
| `vendor_submit_event(event_id)` | `draft`/`rejected` → `submitted` |
| `vendor_archive_event(event_id)` | → `archived` |
| `check_in_booking(reference)` | Returns a **structured result** (`ok`, `reason`, …) rather than raising — "already checked in" / "not found" / "cancelled" are routine states the UI branches on. Atomic on `checked_in_at IS NULL`. Admin bypass since `0022` |
| `vendor_list_team(vendor_id)` | Joins `auth.users` live for email |
| `add_vendor_member` / `remove_vendor_member` | Owner-of-vendor or admin |
| `find_user_by_email(email)` | Resolves an email to a user id. Guarded in `0027` to admins and vendor owners, via a **WHERE-clause filter rather than an exception** so an unauthorized caller cannot distinguish "not allowed" from "not found" |

### Admin-only

Each begins with `if not public.is_admin() then raise exception 'not
authorized'; end if;`.

| Function | Notes |
| --- | --- |
| `admin_publish_event(event_id)` | The only path to `published` |
| `admin_reject_event(event_id, reason)` | |
| `admin_create_vendor(user_id, name, slug, contact_email, contact_phone)` | |
| `admin_set_vendor_status(vendor_id, status, commission_rate)` | The only path to the revoked columns |
| `admin_grant_admin(email)` / `admin_revoke_admin(user_id)` | **Grant only elevates an existing account** — the person must have signed up first |
| `admin_list_admins()` | |
| `admin_list_users(query, limit, offset)` | Paginated. `count(*) over()` carries the total on every row, so one round trip serves both page and count |
| `admin_platform_stats()` | Single row of platform-wide totals for the dashboards |

## Adding to the schema

1. New file `supabase/migrations/00NN_short_name.sql` — next number, never
   edit an applied one.
2. New table → `enable row level security` **and** write policies. A table
   with RLS on and no policy is invisible to everyone.
3. New RPC → authorization check as the first statement in the body.
4. Ask whether the admin app needs a read policy. `ticket_type` was invisible
   to admins for weeks because that step was missed (`0028`).
5. Apply it by hand — see [`operations.md`](operations.md).
